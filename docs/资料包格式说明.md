# 资料包格式说明（format_version 1）

资料包是一个 zip 压缩包，由本地预处理流程生成，管理端只导入成品包，服务器不解析原始文档、不运行 embedding。

## 目录结构

```
<包名>.zip
├── manifest.json        # 包清单（结构见下）
├── vectors.npy          # 全部分块的向量矩阵，float32，形状 (count, dim)，已归一化
├── files/<doc_hash>.pdf # 原文件，文件名为原文 sha256（扩展名保留）
└── text/<doc_hash>.txt  # 标准化原文，UTF-8，无 BOM
```

## 标准化原文与行号

- 行号即物理行号，从 1 开始；引用与分块都以此为基准。
- PDF：每页正文前插入标记行 `[[PDF页 n]]`（n 为实际页序号），标记行占行号。
- DOCX：标题样式处插入 `[[SECTION <标题文本>]]`；表格在 `[[表格]]` 与 `[[/表格]]` 标记行之间按行输出，每行单元格用 ` | ` 连接；不伪造分页。
- Markdown/纯文本：原样保留，`#` 标题行同时作为章节边界。
- 连续空行折叠为一个空行；除此之外不改写、不修正任何原文文字。

## manifest.json

```json
{
  "format_version": 1,
  "preprocessing_version": "v1",
  "embed_model": "Qwen/Qwen3-Embedding-8B",
  "embed_dim": 1024,
  "documents": [
    {
      "doc_hash": "<原文文件 sha256，64 位十六进制>",
      "original_filename": "学生违纪处分办法.docx",
      "doc_type": "docx",
      "title": "学生违纪处分办法（2025 修订）",
      "department": "学生工作处",
      "effective_date": "2025-09-01",
      "audience": ["全校"],
      "domains": [{"tag": "校纪", "section_ids": []}],
      "replaces": null,
      "notes": "",
      "line_count": 120,
      "page_map": [[1, 1], [40, 2]],
      "sections": [{"section_id": "s1", "title": "第一章 总则", "start_line": 1, "end_line": 18}],
      "text_sha256": "<text/<doc_hash>.txt 的 sha256>",
      "chunks": [
        {"chunk_id": 0, "text": "……", "line_start": 1, "line_end": 9,
         "section_id": "s1", "vector_index": 0}
      ]
    }
  ],
  "vectors": {"file": "vectors.npy", "dtype": "float32", "count": 42, "dim": 1024}
}
```

字段约束：

- `doc_hash`：原文文件内容的 sha256；`files/`、`text/` 中的文件名必须使用它。
- `page_map`：仅 PDF 有；`[标记行行号, 实际页码]` 区段起点升序，第一项必须为 `[1, 1]`。查询某行页码时取不大于该行的最后一个区段。
- `sections.section_id`：包内唯一（建议 `s1、s2…`），`start_line/end_line` 为 1 基闭区间。
- `domains`：领域标签，`section_ids` 为空表示标签作用于全文，否则只作用于所列章节（章节级标签）。
- `replaces`：本版替代的旧文档 `doc_uid`（服务器内标识），包内通常为 null，替代关系由管理员在发布时确认；仅当预处理时已明确要覆盖某份现行资料时填写该资料的原文 doc_hash 前缀提示，发布时仍需管理员确认。
- `chunks`：`vector_index` 从 0 开始、跨文档连续且唯一；`vectors.count` 必须等于所有文档 chunks 数之和；行区间必须落在 `1..line_count` 内；`text` 必须与标准化原文 `line_start..line_end` 行逐字符一致（换行符以 `\n` 连接）。
- 向量按 `embed_model` 与 `embed_dim` 生成并已 L2 归一化；查询侧必须使用相同模型与维度，配置变更后必须重建资料包。

## 服务器侧强制校验（与预处理脚本共同遵守）

1. zip 安全：拒绝绝对路径、`..` 穿越组件、反斜杠路径、符号链接项；只允许上述白名单条目。
2. 规模：单包不超过上限（默认 200MB）；解压总量与压缩比（默认 ≤200）超限拒绝（防解压炸弹）。
3. 哈希：`files/` 原文件 sha256 必须等于 `doc_hash`；`text/` 文件 sha256 必须等于 `text_sha256`。
4. 向量：dtype/形状/数量/维度与 manifest 一致，数值有限，范数非零。
5. 结构：manifest 必填字段、日期格式（YYYY-MM-DD 或 null）、section 引用存在性。
6. 包内重复 `doc_hash` 拒绝；服务器端包级 sha256 重复（重复导入同一包）拒绝。
7. 无文字层的扫描件在预处理阶段即被标记退回，不允许进入资料包。
