## 升级与操作

- 安装更新后的 `backend/requirements.txt`，其中含资源采样依赖 `psutil`；前端重新构建。部署保持单进程，使用仓库的可信代理参数和 Nginx 转发头配置。
- 仅接受完整的 v2 备份。v1 缺资料包，不能仅修改版本号升级；需要在仍保存原始资料包的原实例升级程序并重新导出。恢复会还原访问码、管理员口令哈希及令牌签名设置，必要时重新登录。
- 导入受 200MiB 单包、8MiB manifest、4MiB 单文档标准化文本、20000 分块及解压规模等限制；空间不足时拒绝，具体格式见 [资料包格式说明](资料包格式说明.md)。大批资料需合理分包。
- 管理员应确认 `audience_scope`。`confirmed=true` 时空学院或年份数组表示该维度不限；未知自由文本标签不自动猜测。旧包中跨章节的块可能被保守过滤，需要用新版 Skill 重新预处理。
- 新配置使用请求头鉴权，旧 `docs/兼容性验证.md` 的 PASS 不能证明新协议兼容；先运行新版兼容脚本和真实端到端脚本，再人工测试。新版兼容报告默认写入忽略目录 `.local-acceptance/`，不会覆盖旧报告。旧密钥若曾出现在日志中，应撤销轮换并检查留存日志。
- 容量验收必须保留脚本的请求 CSV、连续资源 CSV、摘要 JSON，并核对 systemd/cgroup 的内存峰值和 OOM 状态。0.5 秒采样可能漏掉极短峰值；用量缺失不能估算为零，token 数也不等于账单金额。批量导入的资源峰值仍需单独采样。

## 恢复故障

恢复目录切换前在数据目录的父目录创建 `<数据目录名>.restore-in-progress`。成功或完整回滚后删除；如果进程被强制终止或回滚失败则保留。标记存在时，重启会拒绝初始化，避免把空库误当作恢复成功。

遇到服务持续 503 或启动提示恢复未完成：

1. 停止服务并保全当前数据目录、同级 `.rollback-*`、`.failed-*` 目录和标记，不直接删除或合并文件。
2. 核对故障原因及目录内容，选择包含 `campus.db`、原文件、标准化原文、向量和资料包的完整旧目录；先另行备份，再在同盘恢复为配置的数据目录。不要把不同快照混合。
3. 检查数据库和引用文件完整性，确认模型配置匹配，移除恢复标记后再启动；核对目录、旧引用、草稿和登录状态。无法确认完整性时，从已验证的 v2 备份在隔离环境恢复验证，不强行开放服务。
