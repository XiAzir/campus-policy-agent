## 3. 不得退化的产品与数据契约

### 3.1 范围与非目标

保留完整 React/TypeScript WebUI、IndexedDB 历史、Markdown 安全渲染、原文依据折叠、引用交互及移动端布局。`skill/` 的 Python 本地预处理不重写；`backend/` Python 后端继续作为对照和回滚实现。服务器目标为 Rust 单进程加既有 HTTPS 代理，不增加常驻 Python/Node、Redis、独立向量库或本地模型。

不得以取消分词/HMM、减少合法候选、删除版本约束、抽样向量、ANN、量化、降维、隐藏历史引用或减弱鉴权来压缩内存。模型、embedding 维度/身份、预处理版本、资料包 v1、备份 v2 和既有文档标识不变；这些变更须另立质量/兼容性任务。

### 3.2 范围和引用

用户目录仅列现行已发布资料。默认问答排除停用资料；明确往年可纳入替代停用，手动停用永不参与问答检索/工具原文读取。已发布停用版本的历史引用仍允许经鉴权 HTTP 阅读和下载；不得把这条历史追溯通道误当成 Agent 的范围许可。草稿不得泄露给普通用户。

FTS、向量检索和原文工具必须共同遵守文档/章节领域、明确文件及适用学院/年份约束。明确文件范围只能在用户确认本轮扩展后放开；领域扩展须满足原有原因与查询顺序约束。入队时的判断不能替代执行时、外部 embedding 返回后及证据输出前的状态复核。并发停用不得泄漏被禁止的证据。

工具只允许 `policy_search`、`read_source`、`get_versions`。引用沿用 `EVn` 与 `[[EVn]]`，只认可本轮合法工具注册的证据；文档、行号、页码、章节和摘录来自不可变资料，不信任模型自报位置。无法读取向量、原文或数据库时返回故障，不生成“没有政策”的成功回答。

### 3.3 HTTP、鉴权与 SSE

沿用原始 Spec §6 的 26 条路由、请求字段、鉴权、JSON `detail` 错误及 `frontend/src/types.ts` 事件定义；不得改另一套 API。保留旧 token/口令格式与 Python 互认，换访问码不驱逐已有合法 token，客户端身份取自验签结果。

SSE 保留 `data: <JSON>\n\n`、JSON 内 `event`、现有阶段名、心跳及代理不缓冲契约。一个请求最多一次有效 started 和一次语义终止；错误/取消后无新 delta、无后续工具，扩展确认不伪装成成功 done。实际断线时允许无法再送达 error，但任务必须清理。不得输出原始 thought、thoughtSignature 或内部模型上下文到前端、日志、临时文件或 core dump。

## 4. 资源预算与超限语义

本表是必须保持或补齐测试的契约，不表示每一组合场景都已完成资格测试。MiB 为 1024² bytes，GiB 为 1024³ bytes；字符预算使用 Unicode 标量值，网络/文件预算使用实际字节。硬上限之外还须做磁盘余量及关联一致性校验。

| 对象 | 必须保持的上界/默认值 | 入口与验收要求 |
| --- | --- | --- |
| 普通请求体 | 256 KiB | `api/mod.rs`，缺少/伪造 Content-Length 同样按实际读取限额 |
| 资料包 multipart / ZIP | 210 MiB / 200 MiB | 请求预算含 multipart；ZIP 预算独立；配置不得突破保护上限 |
| 包解压/压缩比/chunks | 2 GiB / 200 / 20,000 | `pkgfmt.rs`；声明和实际读取同时验证 |
| 包 manifest / 单标准化原文 | 8 MiB / 4 MiB | 有界读取；不把所有文档全文和行数组同时常驻 |
| 包中央目录 | 10,002 项且 4 MiB | `archive.rs` 在创建 ZIP archive 对象前预检 |
| 备份请求体 / 解压量 | 各 10 GiB | 请求体含 multipart，不能解释成可上传整整 10 GiB 的 ZIP 再加封装 |
| 备份中央目录 / manifest | 100,000 项且 32 MiB / 16 MiB | 保留备份压缩比和空间预检，不能仅相信声明大小 |
| ZIP64 扩展结束记录 | 固定记录外扩展最多 64 KiB | 实际目录条目/字段长度与结束记录一致；不支持分卷和尾随垃圾 |
| NPY 头 / 维度 | 10,000 bytes / 1..8192 | 二维 native float32、小端目标、有限且归一化；C/F 布局均验证 |
| 候选扫描批次 | 最多 512 行 | 比原始 Spec 的 1024 更严格；按包/行键集遍历全部合法候选 |
| 向量工作缓冲 | 256 KiB | 比原始 Spec 的 4 MiB 更严格；按行宽计算块数，不是服务总内存预算 |
| Top-K / 句柄 | 库 Top-K 上限 256；最多 8 个向量句柄 | 默认两路各 24、RRF 最终 8，不改变默认检索质量 |
| SQLite 单值/编码行 | 8 MiB | `SQLITE_LIMIT_LENGTH`，不是数据库、查询总量或连接总内存上限 |
| DB 连接与队列 | 1 写；读者构造范围 1..8，队列容量 1..1024 | 范围校验不是推荐部署值；沿用当前低资源默认，不新增无界池 |
| 原文 HTTP 窗口 | 闭区间最多 201 行且 256 KiB | 饱和/检查行号算术；工具 read_source 的 40 行限制另计 |
| 问题/历史 | 问题 1..4000 字符；默认最近 12 轮、8000 字符 | 历史入队前单遍裁剪，保持角色、顺序、Unicode 完整 |
| Agent 槽/队列 | 1 个运行槽、默认最多 10 个等待 | 一个 client_id 最多一个未完成请求；不得以提高并发美化吞吐 |
| 工具/证据 | 最多 3 轮，每轮 8 次工具，总证据 192 | 超出显式失败/停止，不绕过范围继续调用 |
| SSE 出站 | 64 个事件且载荷总计 1 MiB | 正常背压；超过 15 秒不消费应取消；字节许可随实际载荷释放 |
| 上游 SSE / 回答 | 单事件 1 MiB，单问答累计事件正文 8 MiB；回答 256 KiB | 超限不中途丢正文再报成功 |
| 模型上下文/parts | 完整往返上下文 8 MiB；单轮保留 parts 最多 4096 个且序列化 2 MiB | 两类预算分别执行；不得剪掉签名/未知字段绕过限制 |
| embedding 响应 | 1 MiB | 流式实际计数；校验维度、finite、非零范数和模型身份 |

硬边界使用 N-1/N/N+1 三点测试；集合同时测试数量小但单项巨大、数量巨大但单项很小。合法历史裁剪和原文分页是协议行为，不应与静默截断答案、证据或签名混为一谈。

参数/角色/范围错误遵循现有 400/422 契约；超体积 413，入队/限流 429，存储冲突 409，恢复维护 503，空间不足 507。DB 队列满须立即返回可识别的脱敏忙错误，不阻塞 reactor；若统一为 HTTP 503，必须在差异表登记并测试客户端行为，不能声称基线所有 busy 路径已统一该状态码。上游故障不可回显响应正文、凭证或内部文件路径。

## 5. 模块实现约束

### DB-01：数据库任务和取消

`db.rs` 普通任务提交采用非阻塞有界投递；排满不能在 Tokio 上同步等待。维护 close/reopen 是控制消息，允许异步等待队列，但必须服从维护时序。取消读任务在执行前或批次边界退出；已开始的发布/恢复必须完成事务或回滚，不能只 drop HTTP future 就提前释放许可。

工作线程 panic 不得永久吞掉连接服务能力，未提交事务须回滚。新增测试覆盖回滚本身失败；不允许在未知事务状态下继续复用连接，应转入明确故障/重建流程。同步 I/O、ZIP、PBKDF2 和大量点积不能在唯一 Tokio 调度线程上长期运行。

输出并核验实际线程、DB 连接、阻塞任务和队列所有权表。若仍依赖默认 blocking pool 规模或存在提交前无许可路径，补齐显式运行时上限与应用级许可后重测；不要把“Tokio 只有一个 worker”当作整个进程只有一个线程的证明。

### RET-01：精确有界检索

保留 jieba 搜索分词/HMM、最多 24 个安全查询 token、FTS5 bm25 方向、点积与 RRF `1/(60+rank+1)`。两路默认各取 24，再融合取 8；同分按原 Spec 稳定 tie-break，浮点差异仅在有证据的容差范围内接受。

按 `(package_id,row_index,chunk_id)` 等等价稳定键遍历，批次上限 512；只留固定 K 的全局最优，不构建全库得分/候选/正文副本。最后命中才读取文档元数据，跨包去重和最终排名须可重复。用全量精确参考计算覆盖 K=0/1/8/24/256、空候选、重复、无序、越界、同分、负分和多包；不把等分样本的偶然排序当成准确率。

NPY C/F 两种布局共享边界策略；校验 shape 乘法/偏移溢出、实际文件长度、dtype、版本和数值，禁止执行头中的 Python 表达式。不在检索失败时返回空成功。不复制整矩阵、修改已发布向量或靠全局 drop_caches 清内存。

允许文档集合、词典、SQLite 及内核页缓存仍有独立成本；“候选/工作缓冲有界”不能推出总 RSS 与库容量无关。新增索引只做兼容加法迁移，并测试 Python 回读与磁盘成本。

### PKG-01：导入、发布和恢复

ZIP 预检必须在第三方 ZIP 库构造目录前执行。中央目录逐项固定头和变长字段不得超预算；EOCD、ZIP64、条目计数、偏移及总长度彼此一致。单次正文读取设实际字节预算；路径穿越、symlink、重复/异常路径、特殊文件、身份/哈希不匹配、非连续向量行号及 chunk/原文不一致仍拒绝。

导入只进入草稿；规范化文本按借用行扫描，避免每行 String 和多份 manifest 深复制。发布完成前旧版本保持可读；失败后文件与 DB 回滚，草稿仍可重试。手动停用优先于替代停用，版本链不得成环或出现未经许可的两个现行版本。

恢复状态为：有界暂存与完整验证 → 获得维护所有权/拒绝新 API → 取消并排空真实读者和任务 → 持久化恢复标记 → 关闭连接/向量句柄 → 同文件系统目录切换 → 重开与校验 → 刷新签发/验签器且保留配置 TTL → 清除标记/退出维护。任意关键步骤失败还原旧目录；回滚失败保留目录与标记、失败锁定。重启发现标记必须拒绝初始化，不创建空库。不得通过关闭 SQLite 同步规避 I/O 故障。

备份含口令 hash 和 token_secret，虽不含模型 API 密钥，也必须作为敏感文件保护；不进公共工件。空间核算包含上传、展开、索引/WAL、快照、新旧目录和至少 128 MiB 余量；失败清理仅触及本次暂存。

### LLM-01：上游与流式生命周期

保留 Gemini 原生 parts 顺序、全部 thoughtSignature、空文本签名 part、functionCall id 与未知字段；functionResponse 对应同一 id。仅非 thought 文本可形成前端 delta。重定向禁用，客户端构造失败不得回退到更弱安全策略。

解析须处理跨网络分片 UTF-8、CRLF/LF、多行 data、空事件和仅 usage/finish 事件；损坏 JSON、半截流或预算超限明确失败。按消费偏移复用缓冲，不逐事件反复整体搬移。Embedding 用数值稳定方式归一化，拒绝极小/极大有限输入计算过程产生的无效输出。

取消涵盖排队、网络等待、背压、检索和工具边界。正常条件目标为取消后 1 秒内释放问答槽；仍在执行的不可中断工作不提前伪报释放。确认任务/FD/队列/字节许可最终回落；不缓存问答正文或 embedding 结果，不以落盘上下文“省内存”。

### API-01：参数、原文与配置

普通 JSON、query、path、multipart 的错误需保持项目 JSON 形式；测试所有极端整数、空值、未知枚举、非法角色、无效 UTF-8 和超长单行。行号闭区间计算使用检查或饱和运算；读取异常与空文件/无匹配区分。

保持环境变量名称及合法默认语义；逐项复核非法/负数/溢出、NaN、Inf、超大队列/历史/TTL/维度。需收紧“解析失败回退默认”等行为时登记为启动契约变更，新增子进程测试并修订计划，不把构造器校验当作所有环境配置已校验。启动必须显式 DATA_DIR，缺密钥或遗留恢复标记拒绝；主机/端口用正确解析支持主机名和 IPv6。不得打印整份 Config 或私有环境。

## 7. 内存、速度与测量资格

### 7.1 继承的门槛

下表继承原始 Spec §3，不把本轮 15.2% 的 Rust→Rust 收益替代 Python→Rust 的迁移目标，不将历史 86.3 MiB RSS 设为硬内存限额。

| 场景 | 门槛 |
| --- | --- |
| D1 分词/HTTPS 初始化和全库查询后静置 60 秒 | 末 30 秒匿名内存中位数 ≤96 MiB，RSS 中位数 ≤160 MiB |
| D1 问答及 10 个同时到达请求，1 运行+排队 | 匿名峰值 ≤128 MiB，RSS 峰值 ≤224 MiB |
| D1 加接近 200 MiB 合法包导入/发布、备份/恢复及允许重叠 | 匿名峰值 ≤192 MiB，RSS 峰值 ≤320 MiB |
| Rust 独立资源资格 | `MemoryHigh=384M`、`MemoryMax=512M`、`MemorySwapMax=0`，完整流程无 OOM、任务遗漏或功能失败 |
| 同条件 Python→Rust | 空闲与问答匿名对应指标下降 ≥40%，问答峰值 RSS 下降 ≥25%；cgroup 对应指标三次中位数 ≤Python 的 105% |
| 稳定性 | 同一进程至少 1000 次问答且至少两小时；尾段同条件静置匿名内存比预热起点增长 ≤16 MiB，资源/任务回落 |
| D1 热态本地混合检索 | 至少 100 次、含全库及过滤；p95 ≤3 秒，且 ≤Python p95 + max(20%×Python p95, 0.05秒)；冷读另报 |

D2 使用授权正式全集，仍须满足功能和 512 MiB 资格；不得拿 D1 数值替代。D3 为 100,000 分块上限探索，失败须给容量/瓶颈证据，不自动推翻已证明的较小规模，也不宣称支持十万分块上线。

### 7.2 公平条件与观测

资格环境为 Ubuntu 24.04、单 CPU 配额、1GB 测试环境；Python/Rust 先在相同 `MemoryHigh=600M`、`MemoryMax=700M`、禁用 swap 条件对照，再对 Rust 做 512M 资格。单核 affinity 不能替代 CPU 配额，完整服务所有线程须在同一独立 cgroup；负载发生器、模拟上游和采样器位于其外并报告部署位置。

每场景至少三次独立进程/数据副本，交替先后顺序，记录每次原始值。数据集和二进制 SHA256、提交、锁文件、编译器、SQLite、词典哈希、CPU/内核/文件系统、有效配置与模拟模式必须可追溯，配置脱敏且不包含完整提示正文。D1/D3 使用固定种子、不同方向的归一化向量，不用零向量/全重复数据取巧。

采样间隔 ≤100ms，关键阶段宜 10ms；同时保留内核峰值与首尾计数，防漏瞬时峰值。记录 RSS/VmHWM/PSS（可获取时）、匿名/文件内存、线程、FD、任务/队列、CPU、磁盘/WAL/临时目录；cgroup 的 current/peak/stat/events/swap 和压力信号；宿主机 MemAvailable 与其他服务用量。缺字段记 unavailable，不填 0、不判 PASS。`high/max/oom/oom_kill` 等事件记录首尾增量；单纯 high 增长不等于 OOM，但要报告回收压力及延迟。

冷/热缓存分开，文件页缓存和 tmpfs 计入解释；普通文件系统失败的运行标记失败，不关闭 SQLite 同步/外键/WAL 以跑通。tmpfs 结果只能与同条件 tmpfs 比较，不算目标磁盘容量认证。不要在正常用户服务器执行全局清缓存。

速度分别记录排队、embedding 等待、本地检索、首字、模型总时间、HTTP 总时间及 CPU；旧 `retrieval_s` 语义保留。新增数值指标只能加字段，并测试前端兼容。按每次运行样本计算 p50/p95/p99，标明样本数和算法；几次 p95 的平均值不能写成合并样本的 p95。

### 7.3 现有脚本与工具缺口

`bench_http.py` 是既有 D1 冒烟/相对测量工具：固定五个 `d1-pkg-*.zip`、`--turns` 仅 1..200、自启 HTTP 模拟器和后端、使用 taskset、无 cgroup 硬限制。它不直接支持 D3、1000 次同进程长稳或正式资格。不可把整个脚本放进 512M 容器后称为“仅后端 512M 测试”，也不可捏造其未存在的 CLI 参数。

`gen_d1.py` 已支持 `--dataset d1/d3`。`sample_memory.py` 已有 `--pid/--cgroup/--out/--interval/--duration`；A3 仍须复核进程退出/文件读取竞争、计数缺失、pressure 及完整 memory.events 等资格需求，不因脚本注释列出某指标就视为已记录。

A3 可新增独立的资格驱动与汇总器，文件名由实现方登记。必须支持外部已启动后端/模拟器、不同包数量、按阶段标记、同进程长稳、cgroup 身份核对和非零失败退出；此处是待实现接口要求，不是可立即执行的新命令。JSON 摘要至少包含 schema_version、commit、binary/dataset hash、environment、scenario、run_index、metrics、gate results，以及 PASS/FAIL/BLOCKED/NOT_RUN 和 reason。

## 10. 发布、回滚与最终完成定义

正式发布前先在副本完成全部技术 gate。检查 `deploy/campus-policy-rust.service`、Nginx、文件权限、DATA_DIR 父目录暂存/rollback 权限、SSE 无缓冲、问答正文不落代理临时文件、恢复 location 上限及 multipart 余量。现有 systemd 的 512M 限制为注释状态；通过资格测试且授权后才启用，不为满足文档提前施加未经验证的限制。

生产切换前停止写入、生成并核验完整敏感备份、保存旧 Python 发布物及配置引用。禁止两套可写服务同时打开一个 DATA_DIR；先停旧实现确认任务退出，再启动 Rust。切换保持域名/浏览器存储键不变。回退先停 Rust，验证 Python 能读取 Rust 期间的新写入；恢复旧快照会丢新变更，必须保存当前数据并取得单独确认，不能自动覆盖。
